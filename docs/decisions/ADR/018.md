# ADR-018: Reference receipt layout and bounded presentation settings

Status: CURRENT owner decision, 2026-10-03. The owner requested implementation of the supplied receipt reference and accepted recommendation, including the existing staging tester URL. This is not production promotion.

One maintained thermal template has business/logo/contact information, order/date/cashier, optional customer information, numbered Item/Qty/Total rows, transaction totals and payment, and a footer. Unit price has its own line. Cash received and Change appear only for cash tender. Empty optional content is omitted.

Extend existing location-scoped ReceiptSettings with optional ReceiptPresentation: templateVersion 1, businessName, embedded bounded PNG/JPEG logo, address, contactPhone, taxRegistrationNumber, footerMessage, showCustomerName, showCustomerPhone and showCashier. Existing shortening/SKU defaults and character bounds remain. The original bounded implementation excluded inheritance; the owner refinement below adds organization defaults in this same settings table. Existing topology has no business branding/contact fields, so receipt presentation owns this bounded output configuration.

At completion, freeze resolved presentation and available customer phone presentation from the existing sale-time CustomerSummary into ReceiptSnapshot. The existing customer adapter supplies phoneMasked; never manufacture or fetch an unmasked phone at printing. Receipts without the new presentation field remain valid and use the legacy template. Reprinting never reads current settings, branding, customer or catalog data. A mutable setting cannot rewrite stored historical content.

Paper width (80mm default, optional 58mm) is an independent local device preference. It changes physical output dimensions without changing sale economics or stored receipt content. A live Management preview and explicitly marked synthetic test print reuse the maintained renderer without creating sale/payment/stock effects. Logos are embedded to preserve reprints and permit offline printing; external URLs and SVG are excluded.

Owner clarification, 2026-10-03 (RECEIPT-TOP-01): preserve the selected printer sheet size and text scale, with receipt content starting at the top. Browser printing must not request a shorter custom sheet based on receipt content: Chromium can center that sheet within the selected longer printer paper. The printer owns page size; the POS retains the local receipt width and small margins. Longer receipts paginate using the selected paper. No new configuration, export feature or stored-receipt change is introduced.

Owner refinement, 2026-10-03 (MANAGE-REMEDIATION-01): configure shared organization defaults and sparse explicit location overrides in the existing receipt settings owner/table. Preserve old full location rows until an administrator explicitly chooses inheritance. Missing overrides inherit; false, blank text and an explicit no-logo value remain deliberate overrides. Saving shared defaults does not silently clear local settings. A separately reviewed **Apply shared layout to all locations** action clears common layout/branding overrides while retaining explicit location address, contact and tax details. The immutable sale-time location name remains separate from branding. Shared/local/bulk changes are tenant-scoped, serialized and audited atomically. Resolved sale-time settings still freeze into the same receipt snapshot; reprints do not read defaults or overrides. No register-level inheritance is added.

Authorization remains Owner/Admin write, managed-location Manager read-only, Cashier/Support no receipt configuration. Mutation and audit remain atomic. Schema changes are additive, v1.0.0 remains canonical, and an additive migration extends the existing settings table/RPC.

Supersedes only the fixed receipt visual layout for newly frozen version-1 presentation receipts. Preserves ADR-003 payload authority, ADR-004 receipt/print separation, ADR-016 immutable product presentation and ADR-017 control-plane authorization. Woo remains commerce authority; configuration never changes totals or invents tax percentages.

Affected contracts: optional ReceiptSettings.presentation, ReceiptSnapshot.presentation/customerPhone, new ReceiptPresentation. WS2 bridge contracts and commerce commands are unchanged. Senior owns schema generation, persistence and integration; bounded WS1 edits are recorded in CURRENT-WORK.

Architecture guardian: PASS. Single POS settings owner, no duplicate commerce truth, no provider API in UI, historical snapshots remain compatible. Exact-head independent human review and fresh automated evidence remain required before staging rollout.
